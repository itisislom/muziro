- **#76**: Переход на студийную архитектуру BandLab — несжатый 32-битный Linear PCM через Web Audio AudioWorklet (BandLab Studio Audio Engine):
  1. **Причина «сжатого» звука из микрофона**:
     - В веб-браузерах по умолчанию для микрофона включена обработка телефонных звонков WebRTC (Acoustic Echo Cancellation, Dynamic Noise Suppression, Auto Gain Control и Highpass filter). Эти фильтры «съедают» дыхание, верхние частоты (воздух) и режут динамический диапазон вокала, создавая ощущение глухого сжатого звука «как из бочки/телефона».
  2. **Студийные ограничения захвата звука (Raw Hardware Capture)**:
     - Внедрен профиль студийного аудиозахвата с полным отключением всех VoIP-обработчиков:
       `echoCancellation: false`, `noiseSuppression: false`, `autoGainControl: false`, а также Chromium-флагов `googEchoCancellation: false`, `googAutoGainControl: false`, `googNoiseSuppression: false`, `googHighpassFilter: false`.
     - Сигнал с микрофонного капсюля теперь поступает в систему 1:1 в первозданном виде — с полной динамикой, теплыми обертонами и прозрачным верхом.
  3. **Технология BandLab: Web Audio API + AudioWorklet (Linear PCM Float32)**:
     - Полностью исключено промежуточное сжатие в кодеки (Opus/WebM).
     - Создан процессор `functions/recording/recorder-worklet.js` (`MuziroPCMWorkletProcessor`), работающий в выделенном реальном времени потоке аудио-рендеринга ОС (Real-Time Audio Thread).
     - Звук оцифровывается в несжатый 32-битный массив с плавающей точкой (`Float32Array`) с квантами по 128 сэмплов с нативной частотой дискретизации звуковой карты (44.1 кГц / 48 кГц).
     - При остановке записи сэмплы бесшовно собираются напрямую в нативный `AudioBuffer` без кодирования и декодирования. Нулевая компрессия (0.00% потерь), студийная точность передачи звука.
  4. **Отказоустойчивость**:
     - Предусмотрена динамическая компиляция ворклета из `Blob URL` на случай блокировки загрузки модулей браузером, а также резервный несжатый `ScriptProcessor` с заглушенным Gain-узлом (`gain = 0`) без обратной связи в динамики.

- **#77**: Устранение задержки старта записи (Pre-warmed Stream) и исправление вылезающего красного блока таймлайна (Zero Latency Recording & Playhead Alignment):
  1. **Ликвидация задержки старта записи (0ms Instant Record Start)**:
     - Ранее после завершения отсчета 3-2-1 срабатывал `setTimeout(350ms)`, а затем только начинался тяжелый запрос к микрофону `getUserMedia` (300-800мс) и инициализация AudioWorklet, из-за чего запись запаздывала на секунду.
     - Внедрен механизм фонового прогрева (`prewarmCapture`): как только пользователь запускает отсчет 3-2-1, микрофонный поток и аудио-ворклет инициализируются в фоновом режиме параллельно с тиканьем таймера (за 2.5 секунды отсчета оборудование полностью готово).
     - При наступлении цифры `REC` искусственные задержки исключены — запись и перемещение плейхеда стартуют в тот же миллисекундный тик (задержка 0 мс).
  2. **Исправление красного блока записи впереди плейхеда**:
     - Ранее DOM-элемент `.live-recording-clip` вставлялся на дорожку без начальных `left` и `width`, из-за чего браузер отображал его с дефолтной шириной внутреннего бейджа (`~95px`), создавая ложный блок впереди или сзади плейхеда. Кроме того, применялось искусственное ограничение `Math.max(8, ...)`.
     - Теперь при создании элемент строго инициализируется со скрытым состоянием (`display: none; width: 0px; left: ${recStartTime}px;`), а минимальное ограничение ширины убрано.
     - Полоса записи строго отслеживает пройденное время `(elapsed / maxDuration) * laneWidth`, располагаясь строго позади движущегося плейхеда, а бейдж с таймером плавно появляется только тогда, когда полоса расширяется более чем на 60px.

- **#78**: Создание защитного модуля `others/blockphone` для блокировки мобильных устройств и обхода «Режима ПК» (Anti-Mobile Shield & Deep Hardware Fingerprinting):
  1. **Создание структуры и компонентов**:
     - В корне проекта создана выделенная папка `others/blockphone/`.
     - `others/blockphone/blockphone.css`: Студийный премиальный дизайн экрана блокировки (темный радиальный градиент, карточка с эффектом матового стекла `backdrop-filter: blur(28px)`, бейдж `Desktop Only · ПК Версия`, SVG-иконка рабочей станции, список ключевых возможностей и требование открыть Muziro с компьютера).
     - `others/blockphone/blockphone.js`: Полностью обфусцированный, самовосстанавливающийся защитный скрипт с защитой от реверс-инжиниринга и отладки.
  2. **Глубокий аппаратный детект (защита от включения «Режима ПК» в браузере)**:
     - При включении тумблера «Версия для ПК» на Android/iOS браузер меняет только `User-Agent`. Скрипт анализирует неизменяемые аппаратные параметры:
       - **Неподделываемый WebGL GPU**: Через `WEBGL_debug_renderer_info` считывается реальный видеочип (Qualcomm Adreno, ARM Mali, Apple GPU, PowerVR). Эти чипы физически отсутствуют на настольных ПК и моноблоках.
       - **Аппаратные точки касания и сенсорный курсор**: `navigator.maxTouchPoints > 1` в комбинации с CSS media query `(pointer: coarse)` и `(hover: none)`.
       - **Физическая геометрия экрана и плотность пикселей**: `Math.min(screen.width, screen.height) < 600` и соотношение сторон дисплея смартфона.
       - **Сенсоры ориентации**: Проверка гироскопа и событий `orientation`.
  3. **Сквозная персистентность (Persistent Jail / Zombie Storage)**:
     - Как только устройство один раз определяется как мобильное, генерируется хэш-токен, который синхронно записывается сразу в три независимых хранилища: `localStorage`, `sessionStorage` и постоянные `Cookie` (срок 10 лет).
     - Если пользователь пытается перезагрузить страницу или переключить режим браузера, скрипт считывает метку и мгновенно глушит страницу до отрисовки интерфейса.
  4. **Анти-реверс и самозащита (Self-Defending Anti-Tamper)**:
     - **AST-обфускация**: Таблица шестнадцатеричных строковых литералов (`\x..`), динамические функции-геттеры со смещением, переименование переменных в хэш-идентификаторы.
     - **Anti-Debugger Loop**: Встроен циклический перехватчик `Function('debugger')()`, замораживающий мобильные DevTools и отладчики.
     - **MutationObserver Watchdog**: Если продвинутый пользователь попытается удалить `#mz-device-guard-overlay` или скрыть его через инспектор элементов (`display: none`, `visibility: hidden`), наблюдатель мутаций DOM мгновенно (за 1 миллисекунду) восстанавливает оверлей и повторно блокирует `body`.
     - **Watchdog Interval**: Каждые 450 мс проверяет целостность оверлея в документе.
  5. **Подключение в ядро веб-приложения**:
     - Защита подключена в заголовок `<head>` файлов `index.html` и `process.html`, гарантируя блокировку мобильных устройств на самом раннем этапе до загрузки тяжелых ресурсов студии.
